# Тестовое задание: AI-помощник для подготовки товарных описаний

Сервис на Python, который генерирует черновик карточки товара для B2B-интернет-магазина на основе входных данных в формате JSON. В качестве LLM используется GigaChat (Сбер).

## Установка и запуск

1. Убедитесь, что у вас установлен Python 3.10+.
2. Установите зависимости. Откройте терминал и выполните: pip install -r requirements.txt
3. Создайте файл .env в корне проекта и добавьте туда ваш ключ авторизации GigaChat: GIGACHAT_AUTH_KEY=ваш_ключ_здесь
4. Запустите скрипт командой: python main.py
5. Результаты появятся в папке output/ в формате JSON.

## Принятые решения и архитектура

- Язык: Python. Выбран из-за богатой экосистемы для работы с API и простоты поддержки скриптов.
- Модель: GigaChat. Выбрана как бесплатное, стабильное и доступное из РФ решение без необходимости использовать VPN и банковские карты.
- Авторизация: Скрипт автоматически получает Access Token по Basic-схеме (Client ID + Secret закодированы в Base64). Токен живет 30 минут, этого достаточно для генерации пачки товаров.
- Отключение проверки SSL (verify=False): В коде намеренно отключена проверка сертификатов, так как GigaChat использует сертификаты НУЦ Минцифры, которые отсутствуют в стандартном хранилище Python.
- Безопасность: Ключ хранится в переменных окружения (файл .env), который добавлен в .gitignore. В коде ключа нет.

## Работа с промптами (Как мы боремся с галлюцинациями)

Главная проблема LLM — они любят выдумывать характеристики. В файле prompts.py мы решили это так:

1. Жесткий System Prompt: Мы запрещаем модели использовать любые внешние знания. Если характеристики нет в JSON — она обязана написать «данных нет».
2. Строгий JSON: В промпте задана четкая структура ответа. В main.py внедрена регулярка для очистки ответа от возможных markdown-тегов, чтобы парсер не падал.
3. Температура 0.1: В настройках запроса к API выставлена минимальная температура, чтобы модель отвечала максимально детерминированно и сухо.
4. Объем текста: В промпт добавлено ограничение на длину seo_description (800–1200 символов), чтобы модель не писала короткие отписки.

## Ограничения решения и что можно улучшить

- Валидация JSON: Сейчас используется стандартная библиотека json и регулярные выражения. Для надежного продакшена стоит добавить pydantic для строгой валидации схемы ответа от нейросети.
- Повторные запросы: Если нейросеть вернет битый JSON, скрипт просто сохранит ошибку в файл. В идеале нужно добавить логику автоматического ретрая (повторного запроса) при ошибке парсинга.
- Веб-интерфейс: По условиям задания CMS и веб-форма не требовались. Однако для удобства контент-менеджера можно обернуть скрипт в FastAPI + простую HTML-страницу с формой загрузки JSON.
- Очередь задач: Для генерации тысяч товаров текущий скрипт не подойдет (он работает синхронно). Понадобится брокер сообщений (например, Celery + Redis).
